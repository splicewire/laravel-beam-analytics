# Analytics Areas

`beam.analytics.areas` holds the **Analytics Areas**: the parts of the Analytics section, each one an `AnalyticsArea` class
keyed by its area key. An area measures a handful of figures. It is drawn as the resource `analytics-{key}`, which is the
area's page, and as that resource's card on the section's overview. The page and the card read one figures path, so they
cannot disagree.

The section is seated in the `operator` and `tenant` realms with an overview, and anyone holding `analytics.view` opens it.
Every area serves both realms. Its reading is in Tenant scope inside a tenant's boundary and in Install scope otherwise, so a
tenant's page and card show that tenant's own figures.

## What ships

**Measurement**, `analytics-measurement`: which tag providers are on, the environments allowed to render a tag, the regions
where Consent Mode denies analytics storage by default, and whether the tag's two slots are placed in a root template. It
shows configuration. It measures no traffic and calls no provider. Each provider is shown with its id: the install's in
Install scope, and in Tenant scope only the tenant's own, read through the `MeasurementSettings` port, never the install's.
Its providers figure links to the host's `site-settings` destination.

**Events**, `analytics-events`: the Event Vocabulary, one row per event a site may report, with its parameters and whether
a package or the host declared it, in the order `x-events` serves them. Every row says "Declared by …", because nothing
records an event firing. Each row links to the host's `site-editor` destination.

A figure links only through a destination the host binds on the `AnalyticsDestinations` port, only where that route
exists and the viewer passes its ability. With no binding there are no links.

## Contributing an area

The generator writes a conforming area and prints the line that registers it:

```bash
php artisan splicewire:beam:analytics:make-area AudienceArea --icon=Users --order=40
# into a package rather than the host's app/ (--path absolute, or relative to the app's base path):
php artisan splicewire:beam:analytics:make-area AudienceArea --namespace='Acme\Accounts\Analytics' --path=/path/to/acme-accounts/src/Analytics
```

It takes the key from the class name (`AudienceArea` becomes `audience`) unless you pass `--key`, and `--label`,
`--icon`, `--order` and `--ability` fill the rest of the `#[Area]`. Before it writes, it refuses a key that is not
kebab-case or that an area already holds. After it writes, it loads the class and checks it the way the registry will. A
finding is printed, the file is left for you to fix, and the command exits 1. A host can publish its own stub at
`stubs/analytics-area.stub`, and the same check applies to what that stub writes.

By hand, write a class that implements `AnalyticsArea` and declare what it is drawn under:

```php
use Splicewire\Beam\Analytics\Areas\AnalyticsArea;
use Splicewire\Beam\Analytics\Areas\AnalyticsReading;
use Splicewire\Beam\Analytics\Areas\Attributes\Area;
use Splicewire\Beam\Analytics\Data\AnalyticsFigureData;

#[Area(key: 'audience', label: 'Audience', icon: 'Users', order: 40)]
final class AudienceArea implements AnalyticsArea
{
    public function measure(AnalyticsReading $reading): array
    {
        return [new AnalyticsFigureData(id: 'members', label: 'Members', value: 12)];
    }
}
```

Then register it from your own service provider. Name the registry as a string, so your package needs no composer edge to
this one:

```php
$this->app->afterResolving(
    'Splicewire\Beam\Analytics\Areas\AnalyticsAreaRegistry',
    fn ($areas) => $areas->add(AudienceArea::class, 'acme/accounts'),
);
```

The class is resolved from the container, so it can take what it reads in its constructor. An area with nothing to
measure returns no figures, and its card is left off the overview: it never shows an invented zero.

## Who can read an area

An area's resource asks for `analytics.view` first. An area can narrow that with `ability:` in its `#[Area]`, and a reader
then needs both. It cannot widen it: an area whose own ability admits everyone still refuses a reader without
`analytics.view`, with a 403 on its page and its card.

## What refuses

All of these refuse where the area is registered, which for a package contribution is boot:

- a key that is already taken, naming both registrants;
- a class that is not an `AnalyticsArea`, or that carries no `#[Area]`;
- a key that is not kebab-case, or that differs from the one its `#[Area]` declares;
- an empty label or icon.
